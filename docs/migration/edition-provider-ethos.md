# ETHOS external architecture publication

ETHOS is a read-only source product, not a Publisher integration target.
Drawing its architecture adds no files, code, dependency, configuration, test
or CI obligation to ETHOS. The independent architecture-publications repository
owns adaptation of selected native facts, editorial choices, artwork and
publication. Neither product needs another source exporter or renderer wrapper.

## Responsibility boundary

ETHOS owns its native facts, domain meaning, repository governance, Work Lanes,
proof, CAS effects and source-product acceptance. The external Edition editor
owns reader questions, adaptation, omission and art direction. Publisher owns
generic layout, native renderer integration, browser and raster observation,
qualification and publication mechanics. Forge custody belongs to the selected
publication owner, not automatically to ETHOS.

Direct or declarative input is valid when selected bytes already exist. An
optional executable Provider may adapt selected native facts only under the
external editor's ownership. It returns standard input, not approval or media;
bounded process supervision is not an adversarial sandbox. No Provider, source
package selection or diagram test is installed in ETHOS.

## Preserve meaning and remove intrusion

The work must preserve intent alignment and compilation, greenfield and
brownfield adoption, repository quality, Lane cooperation and competition,
experimentation and all-drop, object-scoped CAS, accepted integration,
verification, Attestation, runtime admission, recovery and feedback.
Target architecture is not a claim of current implementation.

1. Preserve pinned source material, unique artwork and accepted deliveries
   outside ETHOS before removing dedicated drawing files and every active caller.
2. Pass ETHOS's affected native product regressions and removal acceptance.
   Artwork generation is not a prerequisite for source safety or convergence.
3. Build external standard input through the installed public Publisher entry
   with unchanged source Git state. Native Archify owns HTML; independently
   composed SVG owns PNG6000. Static and interactive media share meaning,
   not geometry or approval.
4. Require parity or an explicitly reviewed successor delta for selected
   meaning and the accepted work, then qualify exact media and relocated use.
5. Apply the external publication owner's custody and remote-readback policy.
   Keep original inputs, failed receipts and exact Git-bound rollback material.

Semantic, artwork, installed capability, source effect and publication
acceptance remain separate. Source removal and external publication each close
through their existing Change; no parallel task ledger is introduced.
