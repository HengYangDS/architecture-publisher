authoring and generic publishing mechanics. Its existing task 9.9.4 owns the
remaining migration. This packet supplies the boundary and acceptance sequence;
it does not authorize ETHOS edits or approve artwork, source or publication.

## Keep meaning, replace duplicated mechanics

The [Authority Matrix](../product-contract.md#authority-matrix) governs the
generic interface. ETHOS owns its native facts, projection interpretation,
domain claims, repository governance, Work Lanes, proof, CAS effects and
source-product acceptance. The named Edition editor owns reader questions,
scope, omissions and presentation. A source product can fill several roles;
physical co-location does not make that arrangement mandatory.

| Responsibility                      | Source-owned successor                               |
| ----------------------------------- | ---------------------------------------------------- |
| Native extraction and meaning       | Minimal ETHOS semantic adapter with explicit loss    |
| Audience and flagship decisions     | Edition authoring and source-specific predicates     |
| Standard inputs and identities      | Publisher's common Build Request, Provider and lock  |
| Layout and rendered media           | Publisher's selected renderer and independent scenes |
| Browser and generic checks          | Publisher observation and qualification mechanics    |
| Acceptance and repository effect    | ETHOS policy and designated accepter                 |
| Forge release, custody and readback | Explicit source-product release owner and custodian  |

An executable Provider may adapt selected native facts into the common input
envelope; declarative or direct delivery is equally valid when those bytes
already exist. It need not maintain a duplicate Claim Model solely to satisfy
the historical transport. It must not return rendered media, qualification,
approval or repository state. Process-tree supervision bounds execution; it is
not an adversarial sandbox.

Move generic packing, derived identity maintenance, Candidate assembly,
browser execution, raster conversion, reader mechanics and local publication
out of ETHOS after their successor consumers pass. Do not transplant mixed
legacy modules wholesale into Publisher. Keep a source-specific composition or
verifier only for a distinct declared predicate. Skills supply replaceable
methods, never another lifecycle or acceptance authority.

## Preserve the flagship's meaning

The terminal architecture must explain intent alignment and compilation,
greenfield and brownfield adoption, repository quality, Lane
cooperation/competition/experimentation/all-drop, object-scoped CAS, accepted
integration, verification, Attestation, runtime admission and continuity.
Neither a single integrated Lane nor an always-merge story represents that
scope faithfully.

Static and interactive media share selected meaning, not geometry or approval.
Preserve the source editor's questions, abstraction, target-versus-observed
notice and visual constraints. English copy, 问道 and an explicitly selected
source poem follow the source-owned language decision. Terminal design must
not be advertised as fully implemented behavior.

OpenSpec and Git are ETHOS's selected carriers, not proof of lossless
replacement by arbitrary SDD and VCS systems. Source adapters must state
revision, relation type, unsupported meaning and transformation loss. Unknown
coverage broadens obligations; it does not authorize silent omission.
