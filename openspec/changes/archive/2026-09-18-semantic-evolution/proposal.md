## Why

The accepted edition can be reproduced, but changed meaning cannot yet become a
new qualified edition or replace an installed pair. ETHOS now distinguishes
unpublished replay, history-preserving merge and exact pending-merge recovery
inside `candidate_base_stale`, without changing node or edge counts. This real
change must not disappear behind identity-only or count-only checks.

## What Changes

- Keep immutable accepted-edition replay and add explicit new-candidate inputs.
- Compare source semantics and conservatively trace changes into authored views.
- Express the selected refresh boundary in the complete static overview and
  complete interactive atlas, using current source and fresh output evidence.
- Extend the existing paired installer for explicitly selected previous ownership,
  exact preimages, managed-file replacement/removal and bounded recovery.
- Qualify real successive editions, publish the new release and verify Documents
  delivery without altering the prior release or predecessor repositories.

## Capabilities

### New Capabilities

None. Existing edition and publication owners gain bounded evolution behavior.

### Modified Capabilities

- `ethos-atlas`: candidate generation, semantic change coverage and standalone atlas.
- `static-publishing`: candidate composition with fresh selected measurements.
- `file-publication`: explicit managed replacement through the existing installer.
- `pair-publication`: new-edition qualification without inherited historical approval.

## Impact

Changes are confined to the publisher's edition, source comparison, publication,
CLI, tests, authored inputs and documentation. No ETHOS product mutation, global
software migration, universal compiler, GUI, graph database or plugin platform.
