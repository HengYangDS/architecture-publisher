## Why

On 2026-11-20 the owner asked where a work states its repository's address, and was shown eighty-six files of the
six works that hold it. He made one source for each fact a hard requirement of everything built here, not of the
address alone. A census of the product the same morning found some forty facts that its source, its schema and its
documents state in more than one place; one of them has already gone wrong, in a reference document that names a
supply one release behind the one bundled.

The queue is where the product's work is ordered. A requirement that no item names is met where it is remembered.

## What Changes

- The queue takes `one-source` before the open rest of `edition-map`: what the product's source forms more than
  once, and the next Changes of `edition-map` build on, stands in one place.
- The queue takes `derived-references` before `performance`: the model's vocabulary is stated once, the refusal
  codes stand in one registry, and a reference document's tables are written from the source.
- `page-figures` says that a guide's diagram file states no repository and no pin: the publisher fills them from
  the model.
- `docs/research/one-source.md` records the census: each fact, where it stands, how it was counted, and what is
  not established.
- The model reference names the bundled icons without their version, which stands in the icons' policy; it said
  1.73.0 where 1.74.0 is bundled.
- The release 0.16.0 is recorded with this Change: it carries each figure alone, the contents and the index, the
  edition's words as its readers read them and the Linux bootstrap kept between jobs, all on dev since 0.15.0.
